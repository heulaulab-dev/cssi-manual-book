# Configuration

The Configuration section lets authorized users manage the request types and system types that appear in development request forms. These configurations determine the available options when creating or editing requests.

<Callout type="warning">
  Configuration management is restricted to authorized users only. If you do
  not see this section in the sidebar, you do not have permission to access it.
</Callout>

## Request Types

Request Types define the categories available when creating a development request. Examples include Feature Request, Bug Fix, System Improvement, or Data Change.

### Request Type table

The table displays all configured request types. Each row shows:

| Column | Description |
|---|---|
| Name | The request type name |
| Description | A brief description of the type |
| Status | Whether the type is active or disabled |
| Actions | Available actions for the type |

### Adding a new request type

1. Click the **Add** button in the Request Type section
2. Enter the **Name** for the new type
3. Optionally enter a **Description**
4. Click **Save** to create the type

### Editing a request type

1. Click **Edit** on the request type row
2. Modify the name or description
3. Click **Save** to apply changes

### Enabling and disabling request types

To hide a request type from the request form without deleting it:

1. Click **Enable** or **Disable** on the request type row
2. Disabled types are not available when creating new requests
3. Existing requests using the type are not affected

## How configurations affect requests

When a user creates or edits a development request, the **Type** and **System** dropdowns show only the currently enabled request types and system types. This ensures that:

- Only approved categories are available for selection
- Deprecated types can be disabled without affecting existing requests
- New types can be added as the organization's needs evolve

<Callout type="info">
  Changes to request types and system types take effect immediately for new
  requests. Existing requests are not affected by enabling or disabling types.
</Callout>
