# Development Requests

Development Requests manage the complete lifecycle of IT development work — from initial submission through approval, assignment, and tracking. The workflow is divided into three main views based on your role: **Develop Request** (submitter), **Develop Accept** (IT approver), and **Develop Approve** (division approver).

## Request workflow overview

A development request moves through these stages:

1. **Draft** — Created but not yet submitted
2. **Pending Approval** — Submitted and awaiting division approval
3. **Revision** — Sent back for changes
4. **Pending IT Accept** — Approved and awaiting IT acceptance
5. **Pending Assignment** — Accepted, waiting for a developer to be assigned
6. **In Progress** — Work is actively being performed
7. **Pending Verification** — Completed, awaiting requestor verification
8. **Done** — Verified and closed

## Develop Request

The **Develop Request** view is where submitters create, manage, and track their development requests.

### Request table

The table displays all requests you have submitted or are involved in. Each row shows:

| Column | Description |
|---|---|
| Subject | The request title |
| Type | The category of request (e.g., Feature, Bug Fix) |
| System | The target system or application |
| Status | Current workflow status |
| Submitted | Date and time the request was submitted |
| Actions | Available actions for the request |

Use the column headers to sort and the search bar to filter requests.

### Creating a new request

To submit a new development request:

1. Click the **New Request** button in the top-right corner of the Develop Request page
2. Fill in the required fields in the dialog:
   - **Subject** — A clear title for your request
   - **Requirement** — A detailed description of what you need
   - **Type** — Select the request category from the dropdown
   - **System** — Select the target system from the dropdown
   - **Attachment** — Optionally attach supporting files
3. Click **Submit** to send the request for approval

### Editing and resubmitting

When a request is sent back for **Revision**, you can edit and resubmit it:

1. Open the request from the table
2. Click **Edit** to modify the subject, requirement, type, system, or attachment
3. Review your changes and click **Resubmit** to send it back into the workflow

The **Develop Accept** view is used by IT approvers to review incoming requests and assign development work.

| Type | The category of request |
| System | The target system |
| Requester | Who submitted the request |
| Div Approver | The division approver who approved it |

| Actions | Available actions for the request |

### Accepting a request

To accept a request:

1. Click **Accept** on the request row
2. The Assignment Panel opens where you can select the developer and due date
3. Select the **PIC** (Person in Charge) from the dropdown
4. Set a **Due Date** for the work
5. Click **Assign** to confirm

### Rejecting a request

To reject a request:

1. Click **Reject** on the request row
2. The Rejection Dialog opens
3. Enter a reason for the rejection
4. Click **Submit** to send the request back to the requester

### Approving a request

To approve a request:

1. Click **Approve** on the request row
2. The request moves to **Pending IT Accept** status
3. The IT approver is notified to review and assign the work

### Rejecting a request

To reject a request:

1. Click **Reject** on the request row
2. The Rejection Dialog opens
3. Enter a reason for the rejection
4. Click **Submit** to send the request back to the requester in **Revision** status

## Request detail view

Clicking on any request in the table opens its full detail view, which shows:

- Subject, requirement, and type information
- System and attachment details
- Current status and workflow history
- Assigned PIC and due date (if assigned)
- Action buttons relevant to the current status
